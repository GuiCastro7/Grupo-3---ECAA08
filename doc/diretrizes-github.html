Engenharia de Software

Padrão de Mensagens de Commit (Conventional Commits)

Tipo Propósito Exemplo de Mensagem
feat: Nova funcionalidade ou implementação de módulo feat(inference): adiciona algoritmo de backward chaining com verificacao de loops
fix: Correção de bug, intertrava incorreta ou falha de sintaxe fix(interlock): corrige condicao de subpressao minima do sensor SP1
docs: Atualização em documentação, memórias descritivos e README docs(etapa-01): atualiza memorial de deducao formal e provas de tautologia
refactor: Refatoração de código sem alteração funcional do algoritmo refactor(karnaugh): modulariza classe de Quine-McCluskey e otimizacao
test: Adição ou melhoria em suítes de testes unitários ou SAT test(sat): inclui testes de refutacao para as 10 regras de diagnostico
chore: Manutenção de configurações, build, CI/CD e dependências chore(pages): configura deploy automatico no GitHub Pages via GitHub Actions
Fluxo de Trabalho

Estratégia de Branches & Pull Requests

# Estrutura de Ramificação do Repositório: main [Branch de Produção / GitHub Pages Estável] └── develop [Branch de Integração Contínua das Etapas] ├── feature/etapa-01-logica ├── feature/etapa-02-redes-petri ├── feature/etapa-03-automatos-dfa └── feature/etapa-04-scada-ihm
📌
Regra de Merge & Revisão por Pares
Nenhum commit direto na branch main é permitido. Todo avanço de etapa é submetido via Pull Request (PR) para a branch develop, exigindo a aprovação de pelo menos um outro membro do Grupo 3.

Matriz Estratégica 5W2H do Projeto Integrador

Mapeamento completo das diretrizes de execução, responsabilidades e cronograma do Grupo 3.

Dimensão Pergunta Definição Estratégica do Projeto (Grupo 3 - ECAA08)
WHAT O que será feito? Desenvolvimento completo de um sistema de automação e supervisão SCADA integrado para controle seguro de uma Linha de Envasamento, Tampagem e Inspeção de Bebidas.
WHY Por que será feito? Para consolidar as competências de modelagem discreta, sistemas digitais, segurança funcional (NR-12 / SIL) e controle por eventos discretos no curso de Engenharia de Controle e Automação da UNIFEI.
WHERE Onde será feito? No ambiente acadêmico da UNIFEI, com repositório hospedado no GitHub e portal técnico distribuído via GitHub Pages.
WHEN Quando será feito? Ao longo do 6º semestre letivo de 2026, com entregas sequenciais cobrindo as Etapas 01 a 04 conforme cronograma do plano de ensino de ECAA08.
WHO Quem fará? Membros do Grupo 3: Guilherme Narciso Castro Silva, Rafael Ribeiro Guedes, Matheus Felipe de Oliveira Agostinho e Nickolas Nicoleto Musico.
HOW Como será feito? Aplicando lógica proposicional, dedução dedutiva formal (SAT Solver), otimização de Quine-McCluskey, sistemas especialistas com motores Forward/Backward Chaining e simulação interativa web (HTML5/CSS3/JS).
HOW MUCH Quanto custará? Custo financeiro direto zero através do uso exclusivo de tecnologias de código aberto (Python, JavaScript, Git, GitHub Pages, Markdown, VS Code).
